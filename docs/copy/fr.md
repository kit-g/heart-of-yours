# French copy review — #441

Reviewed all 1,127 `fr` entries in the master CSV (1,024 app strings and 103 native strings), plus all 134 title/body fields in the 67 in-app release-note items across 20 versions. Store listings and Play release notes are outside this ticket.

Changed 173 CSV entries (159 app, 14 native) and 47 release-note fields. The tables below contain one row per changed string; unchanged strings are omitted. French with the established vous register. Familiar gym terms and short labels are kept when they already read naturally. Validation messages remain neutral, and exercise names are not put in quotation marks.

## Terminology

| Concept | Choice |

| Account linking | associer / dissocier |

- `accountDeleted` announces deletion, while `accountDeletedBody` says it has been scheduled. Keep the scheduling detail; the English title should make the state explicit.
- `resetPasswordBody` says there is no turning back, then offers cancellation. The revised translation preserves the cancellation path; the English sentence should lose the contradiction.

- `programPausedNotice` does not say which weekly count excludes a paused program. The translation keeps that scope instead of inventing a metric.
- `programCalendarSetupNote` implies a shared calendar reveals only the neutral event title. `lib/presentation/navigation/program_calendar.dart` also writes the program, session and exercise list into the event description. The source privacy claim needs a separate correction; this copy pass does not establish calendar-sharing privacy.
- `healthWriteWorkoutsOn` says duration only, while the native permission copy and release notes also mention workout type. Align the English descriptions of the existing write-back fields; this pass changes no health-data scope.

## Patterns

The recurring problems were literal English metaphors in account, import and API copy; ambiguous pronouns; and inconsistent names for training, goals and movement filters. The changes describe the actual action, data or result, while retaining the existing friendly register. Filter help distinguishes technical skill from physical fitness, progression rules distinguish missed targets from short sessions, and chart labels identify the metric being plotted. Release notes use the revised app labels. The native pass follows the same terminology without changing permissions or the device-only health-data promise.

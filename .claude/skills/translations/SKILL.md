# Localizing strings (heart_language)

User-facing copy lives in `shared/heart_language/lib/l10n/`. `intl_en.arb` is the **source
template** — it defines every key and its `@key` metadata. All other locale files
(`intl_en_CA.arb`, `intl_ru.arb`, …) are **generated** from a master CSV; **do not hand-edit
them, `import` overwrites them.**

Round-trip: edit English → **export** to CSV → fill translations → **import** (regenerates the
locale ARBs and runs `gen-l10n`).

## The two commands

Both run from `shared/heart_language/` — the cwd matters, paths inside the script are relative.
(These are the GoLand run configs "export lanuage" and "import translations".)

- **Export** — English ARB → CSV: `dart run scripts/move.dart export`
  Merges `lib/l10n/intl_en.arb` into `scripts/translations.csv`, preserving existing
  translation columns. New keys land with their `en` text and empty cells for the other locales.
- **Import** — CSV → locale ARBs: `dart run scripts/move.dart import`
  Regenerates `intl_<locale>.arb` for every non-English column in the CSV (copying each key's
  metadata from `intl_en.arb`), then runs `flutter gen-l10n` and `dart format --line-length 120`
  on the generated Dart. After this the `L` getters exist.

## Steps to add or change a string

1. **Edit `lib/l10n/intl_en.arb` only.** Add the key and its `@key` block:
   ```json
   "retry": "Retry",
   "@retry": { "description": "Button to retry a failed action", "type": "text", "placeholders": {} }
   ```
   For a parameterized string, declare its `placeholders` here — metadata is copied to every
   locale on import.
2. **Export**: `cd shared/heart_language && dart run scripts/move.dart export`. The new key
   appears in `scripts/translations.csv` with `en` filled and `en_CA`/`ru` empty.
3. **Translate**: fill the empty locale cells in `scripts/translations.csv` (columns today:
   `id, description, en, en_CA, ru`). For `en_CA`, usually copy `en`. For `ru`, follow
   `.prompts/translate-en-ru.md` (repo root) — it has the rules: keep tone/emoji, preserve
   placeholders like `{exerciseName}` and ICU plurals verbatim, match label length. If the user
   has their own translation process, hand off here and stop.
4. **Import**: `cd shared/heart_language && dart run scripts/move.dart import`. Regenerates the
   locale ARBs, runs `gen-l10n`, formats.
5. **Use it**: `L.of(context).retry`.

## Facts and gotchas

- **Never hand-edit `intl_en_CA.arb` / `intl_ru.arb`** — they are regenerated by `import`.
  Only `intl_en.arb` and `translations.csv` are hand-edited; both are committed to git.
- `export` **merges** (keyed by `id`) — it preserves existing translations and never drops a
  column. New locale = add a column to the CSV, then `import`.
- `import` **skips** a locale whose cells are all empty.
- Changed the English wording of an existing key? Still export → (re-translate) → import, or the
  other locales silently keep stale copy. `export` keeps the old translation in the CSV, so flag
  that key for re-translation.
- `import` ends by running `flutter gen-l10n`; you do not need to run it separately.

## Self-check
- [ ] Only `intl_en.arb` was hand-edited (no direct edits to generated locale ARBs)
- [ ] `translations.csv` has the new/changed key with translations filled
- [ ] ran `import` (which ran `gen-l10n`) — `L.of(context).<key>` resolves
- [ ] `flutter analyze` clean where the string is used

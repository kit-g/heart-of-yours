# 1.9.0

## Your workout on the lock screen

Elapsed time, the next set and your rest countdown, on the lock screen — in the Dynamic Island
on iPhone, as a live notification on Android. It is off until you turn it on in Settings, and
tapping it opens the workout.

## Rest timers in one place

Settings now lists every rest timer you have set, across all your exercises, instead of leaving
them discoverable only from the exercise menu during a workout. Clear one from there, with an
undo if you did not mean to.

## What's new, in the app

Settings gained a What's new page: what each update brought, newest first, with the version you
are running marked. It ships inside the build, so it never describes something the installed app
does not have.

## Fixed

- Tapping a workout notification opens the workout you left running, rather than wherever you
  happened to be last.

## Under the hood

None of this is visible, and all of it is why the testing list for this build is long.

- **Analytics.** The app now reports a defined set of events — how sessions become accounts,
  how workouts start and end, which features get used — through one vocabulary class rather than
  ad-hoc calls. Nothing read from Apple Health or Health Connect is ever included, by contract.
  Debug builds, driver runs and Test Lab report nothing.
- **App Check.** The app attests itself to Firebase with App Attest on iOS and Play Integrity on
  Android. Activation only; nothing is enforced yet.
- **Network timing.** The app's single HTTP client is now instrumented, so request timings reach
  Sentry alongside errors. No request headers were added and no traffic is proxied.
- **Removed** the unused remote-config plumbing, which had been inert since the exercise catalog
  moved to an ETag.
- The Firebase iOS SDK moved 12.18.0 → 12.19.0 across every pod, sign-in included.

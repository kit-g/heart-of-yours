## Sign in with Apple works if you already have an account

Signing in with Apple worked exactly once per account. The first time was fine; every time after
that failed with nothing useful on screen. Signing out, reinstalling, or picking up a second
device left you locked out of your own account for good, and there was no way back in from the
app.

The cause was an Apple identity token being spent twice. Linking an Apple account onto the
anonymous session you already have is the normal path, and when that account turns out to exist
already, Firebase refuses the link and the app falls back to a plain sign-in. Both steps were
handed the same token — but Apple honours one exactly once, so the second attempt was a replay.
Firebase reports that as a nonce problem, which is why it read like a signing bug rather than a
credential being used twice.

Firebase hands back a fresh credential on that specific refusal, for exactly this handover, and
the fallback now uses it.

Deleting the Firebase record was not a workaround, incidentally: it frees the Apple ID for one
sign-in, and that sign-in recreates the account and restores the collision.

## Deleting your account works if you signed in with Apple or Google

It did not before, at all. The confirmation dialog asked for a password, and an account created
with Apple or Google never had one — so whatever you typed failed, you were told your
credentials were invalid, and there was no path from there to a deleted account. The button was
shown to everyone regardless of how they had signed in.

Account deletion now re-authenticates the way the account was actually created: an Apple or
Google sheet where that is what you used, the password prompt only where there is a password.
Once the deletion is scheduled you are returned to your profile, instead of being left on a page
managing an account on its way out.

Apple requires that deleting an account also revokes the Sign in with Apple grant, so that the
app stops appearing under Settings → Apple ID → Sign-In & Security and a Hide My Email relay
stops forwarding. That revocation happens on the server, days later, when the scheduled deletion
actually runs — so the app now hands over an authorization code for it at the moment you
confirm. Apple expires those in minutes and honours them once, which is also why the code is no
longer spent on the Firebase credential at sign-in: it was being passed as an access token and
consumed for nothing, leaving nothing to revoke with.

## Google sign-in on Android

Already shipped as `android-1.8.2`, and recorded here because it sits in this range.

Google sign-in had never worked in a Play build. It worked in every local build, which is why it
lasted three months and 317 failed attempts across 21 people. The release build's resource
shrinker was deleting `default_web_client_id` — a string generated from `google-services.json`
that the Google sign-in library looks up by name at runtime, which is a reference the shrinker
cannot see. Its three siblings survive only because Google Play services ships keep rules for
them; the fourth was ours to keep.

It is now pinned in `res/raw/keep.xml`, and the deploy fails if the shrinker ever drops anything
that file asks for — the check reads its list from `keep.xml` itself, so the two cannot drift.

## Attribution for the muscle artwork

The licences page under Settings → About now credits the anatomy illustrations, which are CC BY

registry only reads `LICENSE` files, so the credit had no way to reach you.

## Fixes

Cancelling a scheduled deletion silently stopped working partway through this cycle and was
fixed before release. A dependency upgrade changed `copyWith` so that it preserved the deletion
timestamp instead of dropping it, and the cancel path had been relying on the old behaviour to
clear the flag — so the server cancelled the deletion correctly and the app never noticed, and
kept returning you to the goodbye screen. It now rebuilds the record explicitly, naming every
field it keeps, so the omission is deliberate rather than a side effect of someone else's
signature.

Worth recording: lint was clean and every test passed across that upgrade. Nothing caught it
except using the app.

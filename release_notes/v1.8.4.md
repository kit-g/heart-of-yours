A maintenance release. Nothing new to use — a permanent home for the app's server traffic, and
four things that were wrong on screen.

## The app has a permanent address

Every request the app makes now goes to `api.heart-of.me` rather than the raw gateway hostname it
had been using since the beginning. Nothing about the paths changed, so this is invisible when it
works — which is exactly why it is the first thing to check. A failure looks like empty screens
rather than an error.

## One connection for the session, not one per request

The app had been opening a fresh connection for every single call — a TCP handshake and a TLS
negotiation each time, then throwing it away. That is how `package:http`'s top-level functions
behave when nothing supplies a client, and nothing did.

Measured against the gateway on a wired connection, the handshake was about 25ms of a 66ms call —
roughly a third of it, thrown away and paid again on the next request. On a phone it is two to
three round trips, so 150–300ms each. Reusing one client pays that once per session instead.

The one thing worth watching: a held connection can die while the app is backgrounded, and be
handed back on resume. Idle sockets are timed out, which covers most of it, but the first call
after a long resume is the case to keep an eye on.

## The workout summary screen scrolls

It never did. That was fine for the screen it usually is — a heart count, a line of congratulation,
the workout, and OK — but the personal-records list is exactly as long as the session was good, and
it puts a line there for every exercise that set one. A first workout sets records on *everything*,
because there is no history to beat.

With enough of them the OK button ended up below the bottom of the screen, and with nothing to
scroll there was no way to reach it. The only way out was the close button in the toolbar, which
reads as "discard", not "continue" — at the end of a new user's very first workout.

It now scrolls when it needs to and stays centred when it doesn't.

## Sign-in buttons stopped overlapping their own labels

"Sign in with Google" put the provider's mark in a fixed spot and centred the label across the whole
button, including the strip the mark sat in. Nothing connected the two. English is short enough to
clear it by luck; nothing else is — in Spanish the button read as "GIniciar sesión con Google".

The mark is part of the button now, and the label takes the room that is left, scaled to stay on one
line. This was on four screens: the Google and Apple buttons, on both sign-in and sign-up.

## The mark on tablet login screens

The greeting panel beside the login, sign-up and password-recovery forms — which only appears on a
tablet, which is why this lasted — was drawing the app icon's *web* artwork: the heart baked onto an
opaque white square, because a favicon wants a background. On the panel's dark ground it read as a
white box with a heart in it. It is now the mark alone, tinted to the panel.

## Spanish

The three welcome screens have been reworded.

## Under the hood

Firebase, the notifications plugin and the Android build tooling moved up a version each.
